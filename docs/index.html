The permanent rule

A clip's captions speak the video's own language, or full English — never both, never mixed. When English is chosen, every caption and the hook is translated. It is one pure function (langrule.py) that no flag can bypass. Try it:

In a terminal the tool prompts; for agents it exits with code 2 and prints the exact question, so the agent can relay it to you and re-run with --caption-lang. Why so strict? Because a bilingual stack is how the two languages collide — one caption, one language, always readable.

Six stages, honestly built

Every stage runs locally and prints what it did. Nothing is simulated: each row below is shipped code with tests.

01Transcribe faster-whisper on CPU, word-level timestamps — the raw material for karaoke timing.
02Discover multi-signal moment discovery: every candidate scored and explained, not picked by vibes.
03Cut ffmpeg, frame-exact windows, re-encoded clean (no stream-copy drift).
04Reframe MediaPipe face tracking keeps the speaker centered in 1080×1920; center-crop fallback.
05Captions word-by-word karaoke ASS + a big hook overlay, burned in; layout fitted per script.
06Gates three layout/duration/timing gates validate every export — a violation is a bug, not a warning.
03

The caption gates

Subtitles you can read at 9:16 without squinting. Any file, any time: clipforge subtitles validate --subs-file out.srt

G1

Duration

No cue flashes past unreadably fast, none lingers forever. Readability is a floor, not a suggestion.

G2

Layout

≤ 2 lines, ≤ 42 characters each. Translations are force-fitted (word-wrap, CJK hard-slice, ellipsis cap) so violations are impossible by construction.

G3

Timing

No overlaps, ordered cues, everything inside the clip window. Overlapping captions are a layout bug — gated out.

Quickstart

No API keys for the core loop. Cloud providers (Ollama local / z-ai) are optional adapters for translation.

# install + environment check
pip install -r requirements.txt
clipforge doctor

# transcribe + discover (local, free)
python -m clipforge.cli transcribe --input talk.mp4 --out transcript.json
python -m clipforge.cli discover --transcript transcript.json --audio talk.mp4 --top-n 5

# same-language captions
python -m clipforge.cli render --source talk.mp4 --transcript transcript.json \
    --start-ms 0 --end-ms 46000 --hook "Why three hearts?" --out clip_final.mp4

# full English only — the permanent rule decides the rest
python -m clipforge.cli render --source talk.mp4 --transcript transcript.json \
    --start-ms 0 --end-ms 46000 --caption-lang en --out clip_final.mp4

FAQ

Why can't I get bilingual captions anymore?

The owner made it a permanent rule (issue #17): one caption, one language. Bilingual stacks are exactly what the rule forbids. The --caption-mode flag still exists so old scripts don't break — the rule overrides it and says so in the output.

Why did my render exit with code 2?

The rule needed a human choice: the video's language and your requested caption language didn't match, and it wasn't English. Re-run with --caption-lang <video-language> or --caption-lang en.

Why is the hook also translated?

"Full English only" means nothing in the source language is on screen — including the hook. If the hook translation fails, the render fails; it never falls back to the original hook.

What about subtitles baked into the source video?

Those are pixels in your input file — ClipForge's captions are a separate layer. Removing burned-in text needs cropping or inpainting, which is a different tool.
